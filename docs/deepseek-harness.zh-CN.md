# DeepSeek 原生 dsh 链路

[English](./deepseek-harness.md)

DeepSeek 模型在 Rust agent 入口使用独立的 dsh 工具注册表。普通模型保留 Anya 原来的注册表和提示词；子智能体根据自己的实际模型重新选择。此功能直接实现于源码，不需要 Anya 插件，也不启动或打包 Node harness。

工具 schema、描述、工具提示词、段落顺序和默认身份文本从本地 `deepseek-harness` 导入，当前来源 revision 为 `639ed015397290b3745d163aafe02ffee4aa3f84`。快照、来源和 MIT 许可保存在 `src-tauri/prompts/dsh/`。执行器位于 `src-tauri/src/core/tools/dsh/`。

## 工具与模式

核心配置包含 `read`、`read_image`、`write`、`edit`、`glob`、`grep`、`pwsh`（Windows）或 `bash`、`job_output`、`job_list`、`job_kill`、`todo_write`、`ask_user_question`、`skill`、`web_search`、`web_fetch`、`subagent`、`present`、`exit_plan_mode`。缺少对应宿主能力时不公布该工具。已启用的 Anya 插件工具（`plugin_*`）、MCP 工具（`mcp__*`）和 `manage_plugin` 保留各自的 schema 与执行器，加入本轮 DeepSeek 工具列表；停用或不可用的工具仍不公布。

生图聊天模式只向 DeepSeek 提供 Anya 的 `generate_image` 工具。dsh 适配保留它的 schema 和执行器，DeepSeek 提示词包含已选尺寸、质量、数量及风格要求。实际生图仍需在「设置 → 生图」配置提供商。

### 与普通 Agent 的能力差异

以下差异按当前源码中的注册表和提示词核对；它们不能等同于插件未安装。DeepSeek 使用固定的 dsh 核心工具契约，普通 Agent 使用 Anya 的完整内置注册表。

| 能力         | 普通 Agent                                             | DeepSeek dsh                                                                                  |
| ------------ | ------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| 文件与 Shell | Anya 的细粒度文件工具、`apply_patch`、命令与任务工具   | dsh `read/write/edit/glob/grep/pwsh` 等核心工具；可完成常见文件和命令任务，但没有全部同名操作 |
| 代码导航     | 符号、LSP、代码库索引、Git/工作区专用工具              | 主要通过搜索、读取和 Shell 获取信息；没有对应的专用工具                                       |
| 技能和子任务 | 技能安装/管理、探索/审查/文档工具、并行子任务          | `skill` 加载已启用技能、一个 `subagent` 工具；缺少同名的管理和并行工具                        |
| 应用辅助     | 记忆管理、历史聊天操作、主题管理、Companion 等宿主工具 | 核心契约没有这些内置工具；可用的插件、MCP、`manage_plugin` 会单独加入                         |
| 插件扩展     | 插件提示词与工具前后钩子                               | 插件/MCP 工具可调用，但不注入插件提示词，也不执行工具前后钩子                                 |
| 可选策略     | 多模型协作、精简编码、Companion 来源等提示词           | 当前不注入这些普通 Agent 策略；生图模式单独注入生图策略                                       |

实际工具列表还受本轮模式、权限及工具可用性影响。生图模式的受限工具列表是模式规则，不能用它判断普通 Agent 模式的插件是否可用。

### 文件交付卡片

`present` 的名称、描述、输入 schema 和交付指导从官方导入，Rust 执行器验证本地文件和路径权限，一次最多交付 8 个普通文件。通用 Anya 工具集也提供 `present`，无需启动 Companion 网关。卡片由成功工具结果生成，不扫描最终回复、不把所有修改过的源代码作为交付物，也不复制文件内容。

成功的结构化元数据随 assistant 工具活动持久化，重启后从历史恢复；超过普通工具输出预算时也不会被截断成无效 JSON，交付元数据另有 1 MiB 上限。同一回复中的重复绝对路径采用最新信息，超过四张默认折叠。子任务声明不会自动混入主回复，主模型应再次声明最终交付物。

卡片沿用 Anya 主题变量、图标、边框和圆角，并支持窄窗口。图片点击后使用现有图片预览侧栏；其他文件使用默认应用打开，另有文件夹定位按钮。当前没有引入官方 Office/PDF 侧栏预览或应用选择菜单；打不开时显示可重试错误。文件大小是交付时的记录，文件被移动、删除或修改后，打开行为以当前文件为准。

宿主提示列出本轮实际公布的工具，要求介绍能力时包含 `read_image`。子任务的中间过程使用独立上下文，但返回结果仍占用主会话 token；技能目录来自当前 Anya 配置，不是 dsh 固定自带的技能包。工作区与 Git 状态只依据当前会话上下文或工具结果说明。官方快照保留原文，这些说明作为宿主适配补充。

- 文件读取使用绝对路径、行号、分页、2000 行/行长上限和 50 KiB 内容预算。读取完整文件版本的指纹，长单行不会占用无界缓冲区。
- 写入已有文件必须先读；外部修改使旧观测失效。`edit` 严格匹配文本，多处匹配必须指定 `replace_all`。原有路径审批、Plan 限制、修改预览和检查点继续生效。
- 文件搜索直接执行 ripgrep，按 JSON 解析搜索结果，避免 Windows 路径冒号和中文文件名破坏解析。溢出结果写入工作区侧文件，可用 `read` 继续查看。
- 图像读取限制输入大小和解码内存，超过 2048 像素的图片缩小后传入模型，并返回原图坐标换算提示。
- 前台 shell 到达截止时间后转后台；输出增量领取，任务按会话隔离，完成后提供通知。继续使用 Anya 的命令规则和受限进程入口。
- `todo_write` 替换清单，默认最多一个进行中任务。问题使用稳定 id，等待用户回答或取消。Plan 审批只有用户选择 Approve 才解除写入限制。
- 技能使用 dsh 目录格式和 `skill_content` 包装。Office 技能继续使用已经内置的 Deno、Office Node 和 LibreOffice Kit。

这是一组原生移植的核心工具契约，不是运行整个官方插件生态。网络检索、交互 UI、技能存储、图像文件上传、子智能体和权限由 Anya 的宿主服务承接；子智能体采用官方的前台配置，不公布后台参数。Anya 已启用的 MCP 和插件工具可作为宿主工具使用，包括 Anya 的 computer-use 插件；这不等于移植了官方 harness 的可选 MCP、LSP、PTY、computer-use、团队或续接子智能体插件。不能将本实现描述为所有官方插件和协议都已逐字节复刻。

## 权限与读取预览

原生 dsh 工具复用 Anya 的权限策略、单次审批 UI 与审计记录。只读模式不能通过工具审批提权；工作区写入对非隔离 Shell 调用和外部路径请求审批；完全访问跳过交互审批。这没有复刻官方 harness 的操作系统进程沙箱。

成功的 `read` 结果与通用 `read_file` 使用同一套代码卡片和高亮侧栏。侧栏按记录的读取活动加载文件，文件变化或不可用时回退到快照。详见[权限与代码预览](./permissions-and-preview.zh-CN.md)。

## 请求与诊断

身份、工具指导、技能目录、工作区和项目规则保持稳定；动态上下文和检索记忆放在历史之后。一个 agent turn 内工具定义固定，不经过 Anya 插件的参数/结果钩子。dsh 分支不注入旧工具名的完成挑战或隐式 shell 验证；模型负责根据工具指导验证实际工作。

接近上下文上限时，先在请求副本中缩短超长工具结果，重新测量，仍有压力才进入摘要流程。工具调用 id 和 reasoning 保留。持久化的原始历史不受该裁剪影响。

请求重试只恢复尚未完成的模型轮次；已经提交的工具结果继续保留。可写子任务失败后不整段重跑，避免重复执行写操作。部分流重试清空该次临时内容和工具调用，避免拼接两次尝试。鉴权错误不重试；限流重试遵守 Retry-After。

应用配置目录的 `logs/deepseek-calls-YYYY-MM-DD.jsonl` 保存模型调用和每次 HTTP/流尝试：关联 id、总耗时、首个 SSE、首段正文、缓存命中率、thinking/completion token、重试数与结果。不记录密钥、提示词或工具参数。未上报的字段为 null；错误流没有可用完整统计时不会编造数值。

正常取消也会写入 `outcome: interrupted` 的结束记录，保留已观测到的首事件、正文时间和重试次数。进程崩溃仍可能只留下开始记录。`reasoning_policy` 记录任务类别、原始预算、实际预算和策略版本，关联到同一个 `call_id`。

标题、摘要关闭思考；明确的短普通问答可将高预算降为 Low；代码诊断、项目分析和执行任务保留配置的预算。这个选择是保守启发式，尚未通过真实任务成功率或生产缓存命中率证明性能收益。

### 用真实任务验证预算

默认使用自适应预算。对照组可在启动 Anya 的进程环境中设置 `ANYA_DEEPSEEK_REASONING_POLICY=configured`，保留所配置的预算；实验组移除此变量。用相同模型、相同任务集和一致的验收标准分别运行两组。不要用 API 请求成功代替任务成功。

验收结果以 JSONL 保存，例如 `{"request_id":"实际请求 id","success":true}`；也可用 `call_id` 标注单次调用。一个多轮任务只需标注一次，报告不会按模型调用次数重复计算它的成功率。

```powershell
node scripts/deepseek-metrics-report.mjs "实际配置目录\logs" "outcomes.jsonl"
```

报告按模型、任务类别、实际预算和策略分组，汇总缓存命中、首事件/SSE/正文耗时、token、重试次数和经独立验收的成功率。缺少验收标签时任务成功率为 null；比较时必须使用同一任务集。不会从日志自动编造质量结论，也不使用未经核实的价格计算费用。

## 维护与验证

开发时从指定的 upstream 工作区刷新快照：

```powershell
node --import file:///C:/My/code/deepseek-harness/node_modules/tsx/dist/loader.mjs scripts/sync-dsh-contracts.mjs C:\My\code\deepseek-harness
```

该命令仅用于维护快照；应用运行和打包不依赖该路径。升级快照时必须同时核对 Rust 行为，不能只替换 schema。

本地验证覆盖文件观测与过期编辑、字面匹配、中文路径、分页、后台提升与增量输出、Plan 审批、schema 一致性、提示前缀、DeepSeek reasoning/工具续接和流重试。未调用真实 DeepSeek API，也未据此测量线上费用或打包发布新安装包。

卡片文件图标使用内置 Material Icon Theme 原版 SVG，来源版本和 MIT 许可单独保留，不采用 dsh 的内部设计图稿。通用工具集也支持交付；具体行为与维护见 [文件交付卡片](./file-delivery.zh-CN.md)。
